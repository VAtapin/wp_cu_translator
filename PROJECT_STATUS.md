# Georg-Kloster Slavonic Translator — состояние проекта

## Реализовано

- Опубликованная 1.1.1 содержит переводчик и словарь AZBYKA_CU_FULL через Bible Desktop: поиск по слову/русскому значению, алфавит, пагинация, статья, источник и вставка в переводчик. Шорткоды: [wp_cu_translator], dictionary="no", [wp_cu_dictionary]. Настройки и Installation ID сохраняются.
- Форма следует текущему языку страницы WPML без фиксированного списка локалей и передаёт локаль в AJAX. Стандартный language pack имеет приоритет; встроенный каталог дополняет отсутствующие строки. Пользовательские заголовки зарегистрированы в wpml-config.xml.
- Исходные строки английские. В установочном ZIP сохранены 90 строк и полные RU/DE/UK/PL PO/MO. Каталоговый ZIP исключает PO/MO по требованию WordPress.org. Для импорта подготовлены 93 интерфейсные и 68 readme-строк на язык, включая журнал 1.1.1; проверка блокирует непереведённые новые записи журнала.
- В 1.1.1 Monomakh Unicode загружается из локального assets/fonts/ с SIL OFL 1.1; выбранная буква, варианты алфавита, словарные заголовки и результат перевода используют этот шрифт. Нет автоматической загрузки внешнего шрифта.
- Установочный preview содержит 22 файла и четыре перевода; опубликованный каталоговый ZIP — 14 файлов без PO/MO. Оба архива побайтно совпали с исходниками. На сайты владельца ZIP с компьютера не устанавливается.

## Причина английской формы и пределы исправления

- На https://georg-kloster.ru/kalendarnaya-masterskaya/ сначала подтверждена 1.1.0: asset ver=1.1.0, html lang=ru-RU и скрытая локаль формы ru_RU. Затем владелец показал установленную 1.1.1; настройки и публичная форма остаются английскими. Исправление на его сайте не подтверждено.
- Стандартные georg-kloster-slavonic-translator-ru_RU.mo/.po/.l10n.php на сайте отвечают HTTP 404, тогда как русский каталог другого плагина Calendar отвечает HTTP 200. Отсутствие каталогов воспроизводит английский интерфейс при корректной русской локали. Предыдущее утверждение об устранении проблемы на сайте без проверки доставки пакета было преждевременным.
- На точном опубликованном 11-файловом плагине 1.1.0 без встроенных MO штатный Language_Pack_Upgrader скачал и установил RU пакет с downloads.wordpress.org/translation/plugin/georg-kloster-slavonic-translator/1.1.0/ru_RU.zip. HTML и JavaScript переводчика стали русскими. Это подтверждает загрузку стандартного пакета кодом опубликованной версии; автоматическое предложение обновления на сайте владельца ещё не проверено. Словарная надпись Dictionary и новое короткое описание остались английскими в самом пакете.
- Короткое описание имеет новый оригинал и отсутствует в старом пакете 1.1.0; подробный readme переведён отдельно. Все четыре перевода нового короткого описания есть в исходниках, RU/UK утверждены в GlotPress и вошли в полные пакеты 1.1.1. Исправление интерфейса и списка установленных плагинов на сайтах владельца требует их штатной доставки.
- На основном сайте в авторизованной админке подтверждены ru_RU для сайта/пользователя и корректный slug. Повторный force-check после выпуска 1.1.1 сообщает «Ваши переводы не требуют обновления». Site Health: WordPress.org доступен, HTTP/TLS и фоновые обновления проходят, каталоги WordPress/plugins записываемы. Настройки WPML не менялись.
- На чистом prihod.georg-kloster.ru/?page_id=119 та же английская форма и 1.1.0; WPML среди активных плагинов отсутствует. В штатном plugins/update-check/1.1 JSON-запросе контрольный Calendar определяется и получает RU пакет, Translator отсутствует в plugins/no_update/translations, включая повторную проверку 1.1.1. Минимальные заголовки, альтернативный/пустой PluginURI и прежние filenames не меняют результат; метаданные без доказательства не менялись.
- На проверке 13 октября около 21:00 UTC страница каталога показывает для 1.1.1 задержку выпуска примерно на 6 часов. Официальный код API_Update_Updater не записывает новый выпуск в update_source до окончания cooldown; без прежней записи плагин остаётся вне API. Это соответствует наблюдаемому пустому ответу, но внутреннее состояние сервера WordPress.org напрямую недоступно. Официальное описание: https://make.wordpress.org/plugins/2026/09/09/automated-security-review-for-plugin-releases/ . Доступность после задержки ещё не подтверждена.
- Сначала API translations/plugins/1.0 для version=1.1.1 предлагал неполные пакеты 1.1.0 (66 MO entries с заголовком). На последующей проверке появились полные RU/UK 1.1.1 с updated 20:34:16 / 20:35:27 UTC. Скачанные официальные ZIP содержат PO/MO/l10n.php, все 93 строки, Dictionary и новое короткое описание. API plugins/update-check/1.1 по-прежнему не предлагает плагин или его перевод. Для диагностики не выпускать дополнительные версии без реального исправления: новый выпуск начинает новый cooldown.
- Language_Pack_Upgrader успешно скачал и установил оба полных официальных пакета 1.1.1 в локальном WordPress. Все 14 файлов runtime побайтно сверены с публичным ZIP; встроенные каталоги исключены тестовым pre_load_textdomain фильтром без перемещения файлов. HTML, JavaScript, словарь и короткое описание стали русскими/украинскими. Это проверка установки полученного предложения translations API, а не автоматического обнаружения предложения на сайтах владельца. Проверка с временным перемещением локальной fixture была отклонена automatic approval review; безопасная проверка без backup/перемещения прошла.
- Владелец разрешил выпуск 1.1.1 и необходимых переводов. Установка ZIP с компьютера на его сайты запрещена; используются только штатные пакеты WordPress.org. В текущей диагностике сайт не обновлялся, переводы вручную в его файловую систему не копировались.
