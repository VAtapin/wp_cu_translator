# Georg-Kloster Slavonic Translator

WordPress-плагин для перевода русского и немецкого текста на церковнославянский язык и работы с церковнославянским словарём через [Bible Desktop](https://bible-desktop.com/).

Плагин работает сразу после активации через бесплатный публичный режим Bible Desktop и не содержит OpenAI API key. Браузер отправляет текст в WordPress, а WordPress выполняет серверный запрос к Bible Desktop. Необязательный ключ Bible Desktop API включает повышенные лимиты и не попадает в HTML или JavaScript страницы.

## Установка

Версия 1.0.9 опубликована в [WordPress.org](https://wordpress.org/plugins/georg-kloster-slavonic-translator/) и GitHub Release. Для установки используйте `georg-kloster-slavonic-translator-1.0.9.zip`, для обновления заявки WordPress.org — `georg-kloster-slavonic-translator-wordpress-org-1.0.9.zip`. Установочный ZIP содержит все четыре перевода RU/DE/UK/PL. ZIP для WordPress.org содержит английские исходные строки и POT; переводы для каталога доставляются отдельно через translate.wordpress.org. Исходные PO/MO остаются в репозитории.

1. В WordPress выберите **Плагины → Добавить новый → Загрузить плагин** и загрузите `georg-kloster-slavonic-translator.zip`.
2. Активируйте **Georg-Kloster Slavonic Translator** — бесплатный режим уже готов к работе.
3. При необходимости повышенных лимитов создайте ключ в **Bible Desktop → Система → ИИ-интеграция → Подключение внешних сайтов** и сохраните его в отдельном пункте админ-меню **Georg-Kloster Slavonic Translator → Настройки**.
4. Нажмите **Проверить соединение**. Проверка не вызывает OpenAI и не расходует деньги.
5. Добавьте на страницу шорткод `[wp_cu_translator]`.

Требования: WordPress 6.3 или новее, PHP 8.0 или новее, HTTPS-доступ к `bible-desktop.com`.

## Использование

Основной шорткод:

```text
[wp_cu_translator]
```

С собственным заголовком:

```text
[wp_cu_translator title="Church Slavonic translation"]
```

Форма поддерживает русский, немецкий и автоматическое определение языка, а также ударения, титла, придыхания и славянскую запись чисел. Результат можно скопировать как обычный текст или как форматированный HTML для Word. Ссылка на Monomakh Unicode доступна рядом с результатом.

Название и описание плагина, страница настроек, сообщения и публичная форма доступны на английском, русском, немецком, украинском и польском. Язык выбирается по текущей локали WordPress и текущему языку страницы WPML, без фиксированного списка языков. Пользовательские title обоих шорткодов зарегистрированы в wpml-config.xml. Если каталог выбранной локали отсутствует, остаётся английский источник.

В админ-меню плагина есть два раздела: **Настройки** для адреса Bible Desktop, необязательного ключа и таймаута, а также **Шорткоды** со всеми поддерживаемыми примерами и пояснениями. Такая же краткая справка находится внизу страницы настроек.

## Словарь и шорткоды 1.1.0

`[wp_cu_translator]` показывает вкладки переводчика и словаря. Для прежней формы без словаря используйте `[wp_cu_translator dictionary="no"]`. Отдельный словарь: `[wp_cu_dictionary]`; собственный заголовок: `[wp_cu_dictionary title="Church Slavonic dictionary"]`. Примеры также находятся в административной справке плагина.

Поиск по исходному/гражданскому слову, русскому толкованию и 36 исходным разделам использует модуль `AZBYKA_CU_FULL`. Статья содержит сохранённое написание, гражданский вариант, полное русское толкование и ссылку на Азбуку. Поиск выбранного слова в результате перевода открывает словарь; «Вставить в переводчик» переносит выбранную словарную форму без автоматической отправки на перевод. Морфология, озвучка и автоматическое исправление перевода не заявлены.

Контракт: `GET /api/dictionaries/AZBYKA_CU_FULL/search?q=...&mode=word|meaning&letter=1..36&limit=20&offset=...`, `GET .../alphabet`, `GET .../entries/{key}`. WordPress проксирует только эти пути с nonce и валидацией; HTTPS/TLS и запрет redirect сохраняются. Поиск передаётся после действия посетителя, успешные ответы кэшируются пять минут. Во время финальной проверки использован настоящий локальный Laravel API с 22 908 статьями; production-публикацию подтверждает API/SSH-чат отдельно.

## Расходы и безопасность

- Библейская ссылка, точный стих или уверенно распознанная цитата обслуживаются локальным корпусом Bible Desktop без OpenAI.
- Повторный запрос с теми же параметрами может обслуживаться кэшем.
- Остальные тексты используют общую модель и лимиты, настроенные владельцем Bible Desktop. Бесплатный режим ограничен по числу реальных ИИ-вызовов и обрабатываемых символов.
- При первой активации создаётся постоянный Installation ID (UUID). Это идентификатор установки, а не секрет; он нужен для учёта бесплатной квоты.
- Необязательный внешний ключ хранится только в WordPress options и передаётся исключительно серверу Bible Desktop по HTTPS.
- HTTP, перенаправления внешнего запроса и отключение проверки TLS не разрешены.
- Для минутного лимита передаётся необратимый HMAC-идентификатор посетителя; его IP не отправляется в Bible Desktop. Суточная ИИ-квота считается на Installation ID.

## Разработка и выпуск

Каждая новая запись журнала изменений сохраняется на английском в `readme.txt` и переводится на RU/DE/UK/PL. Сборка проверяет наличие всех changelog-строк в исходном каталоге и полноту четырёх переводов; новая запись без переводов блокирует выпуск. После публикации оригиналов нужно импортировать переводы описания в Stable/Development на translate.wordpress.org, утвердить доступные локали и проверить журнал на локализованной странице. Подготовленный PO ещё не означает публикацию; для DE/UK/PL требуется редактор соответствующей локали.

Номер версии должен совпадать в заголовке `georg-kloster-slavonic-translator.php`, `readme.txt` и Git-теге. Тег версии запускает GitHub Actions, который:

1. проверяет версии и синтаксис PHP/JavaScript;
2. проверяет и пересобирает каталоги переводов;
3. собирает архивы `georg-kloster-slavonic-translator-<версия>.zip` и `georg-kloster-slavonic-translator.zip`;
4. собирает отдельный ZIP для WordPress.org без PO/MO и создаёт GitHub Release с тремя файлами.

После одобрения каталога публикация выполняется GitHub Actions. Используются уже настроенные repository secrets `SVN_USERNAME` и `SVN_PASSWORD` (SVN-пароль из WordPress.org Account & Security), а repository variable `WORDPRESS_ORG_ENABLED=true` включает job. Значения секретов не хранятся в Git.

Для первой публикации существующего выпуска откройте **Actions → Build and release WordPress plugin → Run workflow**, выберите `main`, укажите `version=1.0.7`. `dry_run=true` готовит SVN-изменения без commit; `false` публикует их. Workflow берёт код из существующего тега, проверяет version/stable tag, PHP/JS, каталоги и frontend regression и отправляет пакет без PO/MO в SVN trunk и tags/1.0.7.

Новые теги запускают GitHub Release и затем SVN job автоматически, если release job прошёл. Публикации выполняются последовательно, без отмены уже начатого SVN commit. Новая версия должна иметь новый тег; существующие Git/SVN-теги не переписываются.

Проверены категории из письма о другом плагине: название, принадлежность автору, переводы, внешние сервисы и права публичных обработчиков. Письмо не является результатом проверки этого плагина, а успешный Plugin Check сам по себе не гарантирует одобрения каталога.

- **Название:** применены `Georg-Kloster Slavonic Translator` / `georg-kloster-slavonic-translator`: отличительный бренд стоит в начале. Заголовок, readme, text domain, каталоги переводов, сборка, deploy workflow и smoke-тест согласованы. Название выбрано владельцем; решение о резервировании slug принимает WordPress.org. Если заявка уже подана, запросить изменение slug у Plugins Team. При ручной установке сначала деактивировать предыдущую копию: старый и новый каталоги нельзя активировать одновременно. Настройки, Installation ID и `[wp_cu_translator]` сохраняются; старую копию не удалять через WordPress до переноса настроек, поскольку её uninstall очищает те же options.
- **Принадлежность:** `Author` — Vladimir Atapin, `Author URI` — `atapin.de`, а `Plugin URI` указывает на `kalender.georg-kloster.ru`. Kalendar документирует DNS-подтверждение `wordpressorg-atapin-verification`: оба авторитетных сервера `atapin.de` согласованы, для `georg-kloster.ru` на момент предыдущей проверки оставалось расхождение. При запросе ревьюера следует пояснить связь автора с доменами и Bible Desktop; DNS в этой задаче не менялся.
- **Внешние сервисы:** `readme.txt` раскрывает момент отправки текста, все специальные заголовки, различия между переводом и проверкой соединения, ручную загрузку шрифта, изменение API URL и возможную передачу текста в OpenAI. Документы Bible Desktop `/pages/api-terms` и `/pages/api-privacy` дополнены разделами перевода, UUID/HMAC, OpenAI, кэша и квот; оба сохранены в CMS и проверены на публичных страницах. Исходные тексты и идемпотентная команда обновления находятся в BibleDesktop. Ссылки OpenAI дополняют документы оператора API.
- **Переводы:** исходные строки и встроенные примеры — английские. Все четыре перевода RU/DE/UK/PL сохранены в репозитории и установочном ZIP. Для WordPress.org PO/MO исключены из ZIP и deploy job; POT и i18n-вызовы сохранены для translate.wordpress.org. До публикации языковых пакетов каталоговая версия использует английский интерфейс.
- **Права:** `register_rest_route()` и `wp_register_ability()` не используются. AJAX-перевод намеренно доступен посетителям, включая гостей, и проверяет nonce, язык и размер текста. Nonce не является авторизацией или защитой от исчерпания квоты: её должен обеспечивать API Bible Desktop. Публичный перевод использует общий ключ и квоту установки, если ключ настроен; это должно быть сознательным выбором администратора. Настройки защищены `manage_options` и Settings API; проверка соединения — `manage_options` и nonce. Installation ID и HMAC используются для квот, а ключ не выводится в браузер.
- **Запросы и вывод:** сервер использует `wp_safe_remote_request`, HTTPS при сохранении настроек, проверку TLS и запрет перенаправлений; ввод очищается, HTML экранируется, результат в браузере выводится через `textContent`. Автоматических запросов внешнему сервису при активации или показе формы нет.

Проверены активация нового slug, сохранение settings/UUID, EN/RU/DE-форма с уведомлением о внешней обработке, официальный Plugin Check и структура обоих ZIP. Реальный бесплатный API вернул HTTP 200 для статуса, корпусного и обычного ИИ-перевода; юридические страницы проверены HTTP-запросами без cookies. TXT владения подтверждён на обоих авторитетных серверах каждого домена. Ключевой режим отдельно не проверялся. Письмо WordPress.org не отправлялось, DNS/аккаунт не менялись, новый tag/release и установка плагина на production не выполнялись.
